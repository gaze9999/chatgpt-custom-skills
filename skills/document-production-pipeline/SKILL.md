Pipeline這是一個文件成品產出 pipeline。用途是將使用者的內容、需求、來源與限制整理成可直接交付的文件檔案，而不是只輸出文件草稿或生成 prompt。未指定格式時，預設輸出 `PDF`。使用者明確指定 `DOCX`、`Markdown` 或多種格式時，以使用者要求為準；其他格式只有在執行環境明確支援時才產出。## Pipeline 合約1. 先確認使用者的目標、已有內容、必要來源與明確限制。2. 載入並遵循 [Document Production Guidelines](references/document-production-guidelines.md)。3. 依文件用途建立結構，再撰寫或整理內容；不為了填滿篇幅加入空泛內容。4. 需要外部資料時，只使用能直接支持敘述的可靠來源；涉及可能變動的資訊時先查證。5. 依目標格式建立真正的文件 artifact，而不是以純文字宣稱已產出檔案。6. 產出後進行格式、結構與可讀性 QA；只有實際完成的檢查才能標示為通過。7. 最終回覆保持精簡，提供產出檔案與必要的驗證／限制說明。## 輸入使用者可以自然語言提供，不要求固定欄位。常見輸入包含：- 主題與文件目的- 目標讀者- 已有文字、圖片、表格、程式碼或附件- 指定章節或大綱- 語言與文體- 頁數、篇幅或深度- 輸出格式- 引用／參考資料要求- 文件版本或程式版本- 特定版面、表格、圖表或目錄需求未提供的資訊不要自行補成事實。只有真正阻礙文件正確產出的必要資訊才需要追問。## 格式選擇- 未指定：輸出 `PDF`。- 指定 `DOCX`：輸出可編輯 Word 文件。- 指定 `Markdown` / `MD`：輸出 `.md`。- 指定多種格式：從同一份 canonical content 產出，保持事實、章節、數字、專有名詞與引用一致。- 不因格式轉換擅自刪減內容；只做該格式必要的版面調整。## 文件內容原則- 先建立清楚的資訊架構，再展開細節。- 教學或技術文件優先採「概念 → 實作」「抽象 → 具體」的閱讀順序。- 視需要加入範例、常見問題、模板、檢查表與實戰案例；同類實戰案例集中在同一章節或子章節。- 專有名詞依閱讀順序補充必要說明，不重複堆疊定義。- 保留使用者提供的事實、數字、時間、專有名詞、技術程度與核心意圖。- 不新增無法證實的經歷、成果、API、版本、研究結論或來源。- 避免使用「不是 OO，而是 XX」及同類對照句式。## 文件中繼資料與檔名- 檔名保持簡潔、可辨識、偏學術／技術文件命名方式。- 檔名不加入版本號；版本資訊放在文件內。- 文件內標示 `文件版本`；新文件若使用者未指定，預設為 `v1`。- 文件版本使用 `vX` 形式，例如 `v1`、`v2`、`v3`；每次正式修訂依序遞增。- 文件涉及程式且程式版本可確認時，同時標示 `程式版本`；與程式無關或版本無法確認時省略。- 程式版本使用 `Major.Minor.Patch` 語意並以 `x.xxx.xxx` 顯示，例如 `1.004.012`。- 不捏造無法確認的程式版本。## 目錄與版面- 長文件或具有多層章節的文件，視需要建立目錄。- 標題層級必須一致，避免孤立標題、寡婦／孤兒行與不必要的大量空白。- 表格、圖表與邏輯區塊盡量保持完整；只有內容本身超過一頁時才允許不可避免的跨頁。- 表格跨頁時應重複表頭，避免讀者失去欄位上下文。- 圖表、表格與清單只有在能提高理解效率時才加入。- 不讓視覺裝飾壓過資訊本身。## 各格式要求### PDF- 預設交付格式。- 確保文字可正常顯示，尤其是繁體中文、日文與其他實際使用字元。- 可行時保留可選取文字並嵌入／使用可攜字型，不以整頁圖片取代正常文字排版。- 最終 PDF 的目錄頁碼、標題位置、表格跨頁與頁面留白必須以實際 render 結果檢查。### DOCX- 使用 Word 原生 Heading 樣式建立標題階層。- 目錄使用 Word 原生 TOC field；頁碼使用原生 `PAGE` / `NUMPAGES` field。- 啟用開啟文件時更新 fields（`updateFieldsOnOpen=true`）時，仍需以最終 render 驗證實際頁碼與目錄對應。- 目錄標題靠左、頁碼靠右，使用 dot leader / tab stop。- 標題應與後續內容保持在同頁；避免表格、圖表、程式碼區塊與邏輯段落被不必要拆頁。- 無法避免的跨頁表格重複表頭。### Markdown- 使用清楚且連續的 heading hierarchy。- 不模擬 PDF / Word 的頁碼、分頁或固定紙張版面。- 保持 Markdown 可攜性與可讀性；只有必要時使用表格。- 若同時產出 PDF / DOCX，內容與引用需保持一致，但允許格式特有的版面差異。## 引用與研究- 外部來源必須直接支持相關敘述。- 技術內容優先使用官方文件、標準規格與原始技術資料。- 學術／研究內容優先使用原始研究、系統性回顧、Meta-analysis 與正式學術來源。- 涉及科學、醫療、健康、藥學、心理學或其他以專業研究證據為基礎的領域時，必須使用 APA 第七版格式，包含必要的文內引用與完整參考資料清單。- APA 第七版參考資料有 DOI 時必須提供 DOI；可確認正式出版資訊時不得以不完整二手資訊取代。- 專業領域中的重要事實、統計數據、臨床／實驗結論與具有爭議性的主張都必須有可追溯引用支持。- 不以無法確認、內容不符或純二手轉述來源作為主要證據。- 無法確認的內容明確標示，不以推論寫成已確認事實。## QA產出完成後依格式執行可行的檢查：- 文件能正常開啟，且檔案確實存在。- 標題階層與目錄一致。- TOC 頁碼與實際 heading 位置一致。- 表格、圖表與程式碼區塊沒有不必要的跨頁或截斷。- 沒有孤立標題、明顯 widow/orphan 或過度留白。- 字型與繁中／日文等字元正常顯示。- 多格式輸出之間沒有事實、數字、章節或引用漂移。- 文件內版本資訊與檔名規則正確。- 若可取得 Word / PDF render，應逐頁進行視覺檢查。- 若環境無法 render 或無法完成某項驗證，必須明確標示「未驗證」及原因，不得宣稱通過。## 輸出行為- 條件足夠：直接建立使用者要求的文件檔案。- 未指定格式：建立 PDF。- 指定多格式：交付全部要求的格式。- 不只貼出文件全文後宣稱已建立檔案。- 不輸出內部生成流程或模型推理。- 最終回覆只需列出檔案連結、必要的格式資訊、已完成驗證與尚未驗證項目。
